The same decision — where a completion script goes, and what hint the user is told — is
encoded twice, independently:

- shell: `completion_path()` (`install.sh:197`) and `completion_note()` (`install.sh:215`),
  called from `install_completion()` (`install.sh:228`).
- Go: `resolvePath` (`source/toolkit/internal/completioninstall/install.go:194`), reached from `Install` at
  `install.go:132`.

Both encode the identical three-way strategy (brew `share/zsh/site-functions/_agtk` when
writable, else `~/.zsh/completions/_agtk`; `~/.local/share/bash-completion/completions/agtk`;
`~/.config/fish/completions/agtk.fish`) and the note strings are duplicated *verbatim*.

**Quantified claim:** *no* test in `source/toolkit/internal/completioninstall/` compares the Go paths against
`install.sh`. The package is two files — `install.go` and `install_test.go` — and the tests
assert the Go side against hard-coded literals (`TestResolvePath` at `install_test.go:25`,
`TestResolvePathZshBrewWritable` at `:58`). A change to `install.sh` cannot fail them, and a
change to `resolvePath` only fails a test that has to be edited in the same commit anyway.
The glob anchor is deliberate: what falsifies this is a cross-check file that does not exist
yet (docs/adr/0005).

What breaks when someone changes one and not the other: a fresh install (`install.sh`) writes
the completion to path X, a later `agtk update` (`source/toolkit/internal/cli/update.go:124`) writes it to
path Y. Nothing removes X, so the user keeps a completion script the shell may still autoload,
generated by an older command tree, with no error anywhere.

The opt-out is *not* duplicated in the same way — `AGTK_NO_COMPLETION` is read by
`install.sh:229` on the shell side and by `Install` itself on the Go side
(`source/toolkit/internal/completioninstall/install.go:94`), so a Go caller cannot forget it.
