about: the completion install path strategy exists twice — POSIX sh in install.sh and Go in completioninstall — with nothing holding them together
saw:
  - install.sh
  - internal/completioninstall/install.go
  - internal/completioninstall/*_test.go
---

Kind: **gotcha**.

The same decision — where a completion script goes, and what hint the user is told — is
encoded twice, independently:

- shell: `install.sh:197` `completion_path()` and `install.sh:215` `completion_note()`,
  called from `install_completion()` at `install.sh:228`.
- Go: `resolvePath` at `internal/completioninstall/install.go:184`, reached from `Install`
  at `install.go:122`.

Both encode the identical three-way strategy (brew `share/zsh/site-functions/_agtk` when
writable, else `~/.zsh/completions/_agtk`; `~/.local/share/bash-completion/completions/agtk`;
`~/.config/fish/completions/agtk.fish`) and the note strings are duplicated *verbatim*
("add 'fpath=(~/.zsh/completions $fpath)' to ~/.zshrc before 'compinit', …").

**Quantified claim:** *no* test in `internal/completioninstall/` compares the Go paths
against install.sh. `internal/completioninstall/install_test.go` asserts the Go side against
hard-coded literals (`TestResolvePath`, `TestResolvePathZshBrewWritable`) — a change to
install.sh cannot fail it, and a change to `resolvePath` only fails a test that has to be
edited in the same commit anyway. Verified by reading the only two files in the package
(`install.go`, `install_test.go`) and by
`grep -rn 'completioninstall' --include='*.go' .` -> only `internal/cli/update.go` and the
package itself.

What breaks when someone changes one and not the other: a fresh install (install.sh) writes
the completion to path X, a later `agtk update` (`internal/cli/update.go:124`) writes it to
path Y. Nothing removes X. The user keeps a completion script the shell may still autoload,
generated by an older command tree, and there is no error anywhere — completions are just
subtly wrong. Both sides also read `AGTK_NO_COMPLETION` separately (`install.sh:229`,
`update.go:123`).
