## v0.19.0 — a memory store you can search, hit counts that survive a fresh clone, and a curator that clears what it processed

### `agtk memory search` finds notes without a model call and without reading the whole index

The explorer read all of `INDEX.md` on every delegation (about 3.5k tokens in this repository, about
12k in a larger one) and routed by matching rows itself. `agtk memory search [--files a,b] [words…]
[--limit N] [--json]` does that in the binary and returns a short ranked list:

- **A note anchored to a named file ranks above any note matched on words alone.** `--files` paths
  are normalised to project-root-relative form first (`./a`, an absolute path and a
  working-directory-relative one all match; a path outside the project root is rejected). Glob
  anchors match by string against the path, with no filesystem access.
- **Words** are lower-cased alphanumeric tokens scored over a note's name (weight 3), description
  (2) and body (1), with each term's count capped at 3 per field so a long note cannot dominate.
  Ties break by score descending, then name ascending, so the order is total and stable across runs.
- **Each result** carries the name, kind, confidence, description, the anchors that matched, the
  score, `stale`, and the `agtk memory show <name>` command that opens it. `stale` is the audit
  `show` reports and is only a label: a stale note is not demoted. `--json` uses the shared
  `jsonVersion` and carries no timestamps or hit counts.
- **Search has no side effects.** It records no hit, writes nothing under the store, and warns on
  stderr about a note it cannot parse instead of dropping it. No files and no words is a usage
  error; a query that matches nothing exits 0 with an empty list. The default limit is 5.
- **Notes are read through a small `Corpus` interface** whose only implementation scans `notes/` on
  every call, so a derived index or a different ranker can sit behind the same contract later.
  There is no SQLite, no built index and no MCP server. ADR 0023 records the decision, the
  alternatives rejected and the revisit trigger: a search over a real store that exceeds about
  100 ms. `BenchmarkSearch` over a synthetic 2,000-note store measures about 180 ms, roughly 78% of
  it decoding YAML, and a real store holds tens of notes, so the trigger is not near.
- **`memory-explorer` searches first.** Its second step runs `agtk memory search`; it still opens a
  note only through `agtk memory show`, because `show` records the hit and prints `stale:`.
  `INDEX.md` stays committed and lint-checked, and the explorer keeps its `Read` grant on it.

### Hit counts travel with the branch that earned them

`agtk memory show` records each read in a gitignored log, so a fresh clone reported zero hits and a
cloud session's reads were lost with its container. Now:

- **`agtk memory hits fold [--check] [--json]`** writes one shard,
  `<root>/hits/<UTC-date>-<branch-slug>-<suffix>.json`, holding per note its count and its first and
  last read, and only then empties the log. A shard that cannot be written leaves the log intact;
  a log that cannot be emptied has its shard removed again. It never commits. Every fold has its
  own file name, so two branches never conflict on shards. `--check` exits non-zero while the log
  holds unfolded reads and writes nothing.
- **`agtk memory curate` compacts the shards** into `<root>/hits.json` once verification has
  passed, in the same step that clears processed candidates, and removes the shards it folded. It
  does so on every real verified run, including `--stale`, scoped and limited runs, and never on
  `--dry-run` or after a failed verification. There is no model call. The compacted file is
  written to a temporary file and renamed into place before any shard is removed. An unreadable
  shard is left where it is and reported; an unreadable `hits.json` fails the run and removes
  nothing.
- **`agtk memory stats` reads the compacted file, the shards and the local log together.** The hit
  rate is still distinct notes hit over notes, and a hit counts only for a note that still exists.
  The hit-rate line stops saying "this checkout only" once a committed record exists; reads still
  in the log appear on a separate `unfolded:` line. The `notes:`, `candidates:` and `stale:` lines
  are unchanged, because the session-start hook parses them by prefix.
- **`open-pr` folds before its memory commit**, so the shard lands in that commit, and checks that
  the store root has nothing modified or untracked before it pushes. It first checks that the
  installed `agtk` has `hits fold` and skips the fold with one line when it does not.
  `/memory-curate` gets no such check, because a real curate always leaves tracked changes.

ADR 0024 records the design and the four alternatives rejected: a counter inside each note, one
committed counter file, a committed append-only log, and folding only at curate time. The losses it
accepts all under-count: reads in a session that never opens a pull request, a `hits.json` merge
conflict resolved by taking either side, an unfolded `git checkout`, a note rename, and a read
recorded between a fold reading the log and emptying it. One case over-counts: a shard whose removal
fails after compaction is counted twice until it is removed by hand, and the error names it.

### The curator finishes the job, and unreadable candidates are reported

- **`agtk` clears the candidates the curator processed.** After verification passes it deletes every
  candidate the completion report resolves that is still on disk, and prints each as `cleared:`
  (`cleared` in `--json`). A resolved candidate that is still present is cleared, not a failure;
  nothing is cleared when verification fails or on `--dry-run`; only ids from the pre-run snapshot
  are ever removed.
- **A candidate the run neither resolved nor reported fails an unscoped run.** An unscoped,
  unlimited, non-stale, non-dry-run run that ends with a candidate on disk that is not in the
  report exits non-zero and lists it. Scoped, limited, stale and dry-run jobs may legitimately
  leave candidates and are exempt.
- **Unreadable candidates are named.** `agtk memory lint` reports a candidate whose YAML does not
  parse, with the file and the error, and exits non-zero while any remains; `curate` reports them
  at the end and exits non-zero too. The curator is told they are not its to fix. ADR 0022.
- **The curator's reads are not hits.** Its `agtk memory show` calls pass `--no-hit`, and the line
  the generated index prints about `show` names the flag.
- **Writers quote `about:`.** The explorer's candidate template and `open-pr` say to wrap it in
  double quotes, and `open-pr` runs `agtk memory lint` after staging.
- `/memory-curate` reads the store root from `agtk memory stats` instead of assuming `.memory`,
  and ends by handing the commit to the session.

### `agtk code-review` falls back when a provider is not installed

On a machine without a provider's CLI (no `codex` on `PATH`, for example), a panel whose unanswered
runs all hit the missing provider now retries once on its declared `fallback:` panel and says so:
`fallback: deep-codex -> deep (provider missing)`. A review that is still unavailable after that,
or whose panel declares no fallback, still posts its "no verdict" to the pull request; only a
credential block keeps a review off the pull request. The fallback line, the posted body and the
run record name the cause. A run counts as a missing provider only when the error arose before
anything started, so a timeout, a crash or a cancelled run stays an ordinary failure (ADR 0021).

### Also in this release

- **JSON additions, all additive.** `agtk memory stats --json` gains `local_hits`, `shards`,
  `compacted` and `unreadable_hits` (never null; `[]` when every record was read). `agtk memory
  curate --json` gains `cleared`, `unreadable`, `compactedShards` and `unreadableShards`.
- `CONTEXT.md` gains **Search**, **Hit shard**, **Clearing** and **Unreadable candidate**, and
  reworks **Index**, **Hit**, **Hit rate** and **Cold**. The consumer guide's memory section lists
  every `agtk memory` subcommand, including `search`, `hits fold` and `candidates`.

### Compatibility

- **No schema changes.** The `fallback:` description in `definitions/CONFIG-SCHEMA.md` now names a
  missing provider as a trigger, and nothing else in either schema document moved.
- **A store indexed by an older `agtk` fails `agtk memory lint` after the upgrade** with
  `index is out of date — run agtk memory index`. The generated index's `show` line names
  `--no-hit`, so a committed `INDEX.md` written before this release no longer matches what the
  binary renders. Run `agtk memory index` and commit the result; a CI job that lints the store is
  red until you do.
- **`agtk memory lint` and `agtk memory curate` exit non-zero** where they used to exit 0: on a
  candidate whose YAML does not parse, and, for an unscoped `curate`, on a candidate the run left
  behind without reporting it.
- **The memory stack pre-approves one more command**, `Bash(agtk memory search*)`, so what it
  renders for an existing consumer changes.
- **The catalog and the binary go together.** `memory-explorer` at this release calls
  `agtk memory search`, which an older `agtk` rejects, and there is no fallback to reading
  `INDEX.md`. Upgrade the binary before, or in the same step as, moving the ref.
- **Existing stores need no `.gitignore` change.** The store's own `.gitignore` covers only the
  local log, so `hits/` and `hits.json` are committed by design.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`), then `agtk memory
  index`, and commit. Consumers pinned to a tag can bump the ref in `.agentic-toolkit.yaml` to
  `@v0.19.0`.
- **Building from source still requires Go 1.26.6.**
