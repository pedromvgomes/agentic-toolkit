## v0.13.0 — a stack can ship the grants its definitions need, and the panel is spent where the risk is

Two of this release's three changes come from the same defect in different clothes: a key with one owner, and a rule that fired on everything. `permissions` had exactly one owner per render, so a stack that bundled an agent had nowhere to put that agent's grants. The escalation rules raised to `deep` on almost every branch, so the most expensive reading was the routine one and `quick` — the declared worktree default — almost never ran.

### `permissions` composes across settings definitions

A settings definition's `permissions` is merged rather than replaced. `allow`, `deny` and `ask` union across every definition that contributes them, deduplicated on the exact rule string and ordered by stack so a render stays reproducible. Every other top-level key is still last-wins.

Without this the key has one owner per render, and the direction of the loss is the damaging one: a stack's own entries sort after everything it extends, so the grants that disappeared belonged to the stack being reused — silently, because a same-key collision between settings definitions raises no diagnostic.

```yaml
# stacks/memory.yaml ships the definitions and the grants they need
settings: [memory-permissions]

# stacks/default.yaml extends it and keeps its own
extends: [./memory.yaml]
settings: [skill-permissions, feature-flow-model]
```

Both arrive. Before, `skill-permissions` took the whole `allow` list from `memory-permissions` and nothing said so.

A `permissions` member that is not the list its name promises is refused with an error naming the definition that wrote it, rather than composed past — dropping somebody's grants quietly is the failure this exists to prevent, and the author of a shared stack is not the person running the render.

### Memory is its own stack

`stacks/memory.yaml` carries the store and everything that reads it: the `memory-explorer` agent, the `memory-curate` and `memory-seed` commands, the memory-first instruction, the two session hooks, and `memory-permissions`. `stacks/default.yaml` extends it.

Adopting memory no longer means adopting the feature flow with it. `memory.root` is deliberately absent from the new stack — it is honoured only in the consumer's own entry manifest, so where a repo commits its notes is not a shared stack's business.

This is also the first release in which a memory-only consumer works at all. The claude adapter appends the store-path grants onto an allow list some definition has already contributed, so a stack shipping the explorer and no permissions rendered an explorer that prompted on every delegation, with nothing in the catalog saying so.

A consumer of the default stack receives the same grants it received before: the set is unchanged and so is every other settings key, with only the order of `allow` shifting, because an extended stack sorts ahead of the stack extending it.

### The panel is spent where the risk is

Three changes, each aimed at one reason `deep` fired.

**`fix-revert` split.** Its pattern matched `fix`, and under Conventional Commits that is a type prefix on a large share of every subject line — so a signal meaning "these lines trace back to a deliberate repair" named most lines in a mature tree. It now means what its name says: a revert, a hotfix, a security repair, a CVE. Routine repairs are reported as the new **`bugfix-lines`** signal and raise to `standard` — a reason to read more of a change, not to read every axis of it twice.

**`auth` distinguishes a directory from a name fragment.** `**/auth/**` names a directory that is what it is called, and a file under it is auth code whatever the diff says. The fragments — `**/*auth*`, `**/*middleware*`, `**/*interceptor*`, `**/*guard*`, `**/*permission*` — establish the signal only on a file that is called rather than read, which keeps `guards/admin_guard.ts` and drops `config/guard-settings.yaml`.

The fragments matter more than they look. The dangerous edit to a gate is the one that deletes the check, and deleting a check deletes the words that name it, so the content pass cannot see it. `\bpermission` has no word boundary inside `HasPermission`.

**A pull request caps at `standard`.** The branch has normally been through the local loop by the time it is opened, so an every-axis-twice reading there re-reads code already read that way. `deep-codex` stays a panel and stays `deep`'s fallback; reaching it on a pull request is `--panel deep-codex`.

Nothing verifies that the local loop ran. It posts nothing, approval reads only what is posted on the pull request, and the author — whose machine that loop runs on — is the party a review exists not to trust. An author who skips it gets the shallower reading and no one is told. That is the price of not paying for the deepest panel twice on every branch, it is recorded in both manifests, and a repo that disagrees raises it back by naming `deep-codex` in a pull-request rule.

**Size raises at 50 changed files** rather than 20.

### Fixes

- The `skill-permissions` definition drops `Write(./.agents/memories/**)`. Serena keeps its memories at `.serena/memories/`, writes them through its MCP server's own tool, and is governed by `mcp__serena__*` rules rather than file-path ones — so the grant named a path that does not exist, inside a tree the codex adapter renders and prunes, through a rule family the file permission check does not consult.
- The stack-requirements check follows `extends:` by local path. A requirement reached through an extended stack is satisfied, and reading each manifest alone reported a consumer losing a definition it actually receives.

### Compatibility

- **Manifest addition:** the `bugfix-lines` signal. Manifests decode strictly, so upgrade the binary before naming it in a rule.
- **Breaking — `permissions` composes.** A consumer that narrowed an extended stack's grants by setting its own `permissions` now unions with them instead of replacing them. Narrowing is spelled on the side you want: `deny` refuses outright, `ask` turns a pre-approval back into a prompt. Both compose the same way `allow` does.
- **Breaking — pull-request reviews cap at `standard`.** Every consumer without a manifest of its own inherits this. A repo that wants the old reach names `deep-codex` in its own pull-request rules.
- **Breaking — `fix-revert` no longer fires on a routine `fix(scope):` commit.** A manifest that wants routine repairs to raise names `bugfix-lines` alongside it.
- **Breaking — `auth` no longer fires on a name fragment alone outside an auth directory.** A file merely named for a guard raises it only when the file is code; a settings file named for permissions raises it on what its content says.
- **The memory definitions move to `stacks/memory.yaml`.** A consumer extending `stacks/default.yaml` needs no change: the default extends the new stack and renders the same set. A consumer that listed the memory definitions individually keeps working, and can extend `stacks/memory.yaml` instead.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`), then `agtk lock` and `agtk sync`. Consumers pinned to a tag also need to bump the ref to `@v0.13.0`. Read your rendered `.claude/settings.json` if you had been narrowing a stack's grants by omission.

### Known gaps

- **The panel reallocation does not apply to the pull request that introduces it.** The manifest is read from the base ref so a branch cannot write the rules it is judged against, which is correct and means the saving begins on the next branch.
- **`auth` still fires on the word "permission" in changed content.** The path rule is narrowed; the content rule is not, so a change to a settings file whose body says `permissions:` still escalates. Keeping it is deliberate — a repo whose authorization code says "permission" and never says "rbac" or "authoriz" would otherwise go quiet.
- **Nothing records that a local review ran**, so the pull-request ceiling rests on a claim the pipeline cannot check, and the posted review does not say when an escalation rule would have gone above it.
- **The codex adapter resolves `permissions` last-wins**, where the claude adapter composes. No definition targeting codex contributes the key today, and the divergence is pinned by a test rather than left for a reader to guess at.
