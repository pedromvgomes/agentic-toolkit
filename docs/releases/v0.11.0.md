## v0.11.0 — the memory store, and a binary that can read the manifests it needs

The first release since v0.10.1, and the one that makes the memory subsystem reachable at all. Everything in it — the notes, the agent that reads them, the hooks that route to it — depends on a `memory:` key in `.agentic-toolkit.yaml` and on an `agtk memory` command, and **no published binary had either**. Manifests decode with `yaml.Strict()`, so a released `agtk` pointed at a manifest that sets `memory:` does not ignore the field, it fails:

```
$ agtk sync
agtk: failed to parse stack manifest
  file:    .agentic-toolkit.yaml:17:1
  reason:  unknown_field
  detail:  [17:1] unknown field "memory"
```

That is why this release exists. Upgrade the binary first — `agtk update`, or re-run `install.sh` — and only then set `memory:`.

### New: `agtk memory` — a repo-resident store of durable notes

A store of what cost real exploration to learn about your own codebase: invariants, rationale, gotchas, dead ends. Notes are markdown with frontmatter, committed alongside the code, so they are reviewable in a PR and travel with the branch that wrote them. The store lives at `.agents/memory/` by default.

Eight subcommands, all of which take `--json`. Exactly one of them writes to `notes/`:

| command | writes | exit |
|---|---|---|
| `index` | `INDEX.md` (scaffolds the store) | 0 |
| `anchor <name>…` / `--all` | note frontmatter — blob hashes, glob expansion | 0 |
| `audit` | nothing | 1 if any note is stale |
| `lint` | nothing | 1 if the store is malformed or the index is stale |
| `show <name>` | `.hits.jsonl` (gitignored) | 0 |
| `stats` | nothing | 0 |
| `candidates` | nothing | 0 |
| `curate` | `notes/`, via a model | 0 |

Three properties are worth knowing before you adopt it:

**Staleness is computed, never stored.** A note anchors the files its claim rests on, and `agtk memory anchor` records the git blob hash of each. `audit` recomputes them and reports drift, leaving no diff of its own — which is what makes it safe to run from a hook and from CI. Hashes are computed in-process (`sha1("blob <len>\0" + content)`), so the check needs no repository, reflects uncommitted edits, and is testable from a temp directory. Content, not commits: squash merge makes branch commits unreachable, so a `git diff <commit>..HEAD` check would hard-fail rather than degrade. See ADR 0001.

**`confidence` and staleness are independent.** Confidence is a curator's judgment that a claim was checked; staleness is a pure function of current file content. Letting the second overwrite the first would destroy a verdict only a model can produce.

**`anchor` refuses a bare invocation.** Stamping does not only record hashes — it clears the staleness signal, the one thing telling the next reader that nobody has checked a claim. A bare `anchor` after a refactor does that to every note in the store at once, silently and permanently, since no later audit flags it again. It now requires note names, or an explicit `--all` for a deliberate whole-store sweep, and refuses both together.

### New: the definitions that make the store get used

A store only repays its cost if it is consulted *before* an exploration is repeated, so routing is part of the feature rather than an afterthought. `stacks/default.yaml` gains:

- **`agents/memory-explorer`** — answers *understanding* questions. It reads `INDEX.md` first, opens a note only when its anchors intersect the task's files, reads it through `agtk memory show` (never by opening the file, because the command is what records the read), treats a stale note as unverified, and stages what it learned into `candidates/`. It deliberately does **not** take location questions — "where is X", "what calls Z" — which grep and an LSP answer in seconds and which the store does not keep.
- **`instructions/memory-first-exploration`** — the constant-size rule that makes delegation happen. It distinguishes three outcomes of `agtk memory stats`, not two: no binary and `notes: 0` mean explore normally, while **a non-zero exit means the store is present and unreachable** — report what it printed and keep delegating. Collapsing those is how one YAML typo silently switches memory routing off in the repo with the fullest store.
- **`hooks/memory-claude-session-start`** and **`memory-claude-session-end`** — a session-open digest of store size and staleness, and a session-close line naming what this session staged. Both report; neither acts. A hook that curated would fire a model call implicitly, which ADR 0002 rules out. Both print nothing when the store is empty and exit 0 when `agtk` is absent, so a repo that has not adopted memory pays nothing.
- **`commands/memory-curate`** — runs the curator over the staged backlog, or with `--stale` over notes whose anchors have drifted.
- **`commands/memory-seed`** — the cold-start sweep. It fans `memory-explorer` out over 4–8 areas of the repo grouped by concern and hands off to `/memory-curate` rather than curating, so the sweep adds no second author to `notes/`. It replaces the explorer's usual bar for its duration: *what cost real exploration* selects everything in a cold read, so the sweep asks instead **would a competent engineer reading this get this wrong?** No target note count — a number handed to a sweeping agent is an instruction to keep going until it is met.

### The curator is the only author of notes, and it ships in the binary

Curation is the one memory operation that calls a model. It has no definition: the prompt is embedded in `agtk` (`internal/curator/prompt.md`) and handed to the provider as an agent roster, with the tool grant **constructed in Go** and passed as `--allowedTools`. That turns ADR 0003's single-writer rule from prose into an argv flag no settings file can widen. The price — the curator loses its lockfile pin — is recorded in ADR 0004 with the alternatives weighed against it.

`agtk memory curate --check` resolves provider, binary, permission mode and grant and starts nothing, so confirming the configuration never requires performing it.

Two things the grant learned the hard way, both of which are now guarded by tests:

- **The deletion grant is scoped to the store's own `candidates/`**, threaded through as a parameter since `memory.root` is configurable. An unset root yields no deletion grant rather than composing to `rm /*`.
- **The stamping grant names each note exactly.** `Bash(agtk memory anchor <name>*)` stops short of a second *argument*, not of a longer name in the same one — and names are kebab-case, so a grant for `lockfile-pins` also permitted `lockfile-pins-shas-not-tags`. A run could then mark fresh a note it never checked.

No `--permission-mode` is passed. `acceptEdits` auto-approves every file edit anywhere, which outranks the allowlist and would leave the constructed grant as decoration.

### New: `memory.agent: codex`

Codex was advertised in help and failed on every real invocation, while `curate --check` reported it as ready. Confinement is now **discovered by asking the provider**, never by switching on its ID: the per-tool allowlist is offered first, and a provider that refuses it falls back to a sandbox mode validated through that provider's own permission arguments.

A run that writes notes is refused where there is no per-tool allowlist, rather than silently widened:

```
$ agtk memory curate --check
agtk: codex has no per-tool allowlist, so a curation run that writes notes cannot be
confined to the store on it; re-run with --dry-run, which is bounded by the "read-only"
sandbox, or point memory.agent at a provider that grants tools
```

The narrowest sandbox that would let it write covers the whole workspace, and taking it would falsify what the store's own notes say about the grant. A preview writes nothing, so `read-only` expresses `--dry-run` exactly — and enforces it, rather than asking the model to hold back.

### `requires:` is resolved, not merely declared

A definition could declare that it does not work alone, a stack could list it without its dependency, and the omission survived parse, resolve *and* render — surfacing in a consumer's session at the moment something dispatched to an agent that was never installed. That is how `wrap-session` shipped broken to every consumer.

The resolver now pulls in anything a resolved definition requires that no stack lists, **transitively**, and reports each one:

```
$ agtk plan            # a stack listing only wrap-session
definitions:
  agents:
    - wrap-session-reviewer
  skills:
    - agents-md-creator
    - wrap-session
diagnostics:
  [pulled_requirement] skills/wrap-session requires agents/wrap-session-reviewer, which no stack lists; pulling it in
  [pulled_requirement] agents/wrap-session-reviewer requires skills/agents-md-creator, which no stack lists; pulling it in
```

This mirrors what the resolver already did for sources: an entry needing something the stack does not name gets it, locked like any other, reported and not fatal. A requirement is the same relationship one level down.

A requirement resolves in the same source and under the same root as the definition that declared it — a URL entry's requirement root comes from the entry's own in-repo path, not from the listing stack's filesystem. Reaching the depth bound is reported, because a truncated closure leaves definitions missing while the render looks complete.

### Fixes

- **`sync` re-locked on a fresh clone and failed offline.** `lockIsStale` compared mtimes, and `.agentic-toolkit.lock.yaml` sorts before `.agentic-toolkit.yaml`, so the *first* `sync` after a clone always saw a stale lockfile. The lockfile now records a digest of the entry manifest and staleness compares content.
- **An advanced branch read as corruption.** `FrozenProvider` fetched by ref and checked the SHA afterwards, so a branch that had moved failed as `ErrSHAMismatch`. Two recoveries after the shallow fetch, with deterministic hydration order.
- **An empty `config.yaml` silently disabled auto-update.** It returned `io.EOF`, which `root.go` discarded. `io.EOF` now takes the missing-file path, decoding into a separate value since the decoder zeroes its destination before reporting EOF.
- **The update throttle only advanced on success**, so an offline `agtk` hit the GitHub API on every invocation. A failed attempt now advances the timestamp while preserving the version it learned nothing about.
- **`AGTK_NO_COMPLETION` was documented and never read** by `Install`. Enforced there as well as in the caller, via a shared constant.
- **`renderCommand` emitted a command's tool allowlist under `tools`**, which Claude Code ignores — the restriction was dropped in silence, permissively.
- **`agtk memory <anything>` exited 0 and printed help.** Cobra rejects an unknown subcommand only at the root; a non-root parent takes it as an argument. An agent told to run a subcommand its `agtk` lacks would have read the help text as output and reported success.

### Repo and CI

- Coverage is measured with `-coverpkg=./...`. Tests live in sibling `internal/<pkg>/tests` packages, so the previous gate credited coverage to the package *running* the test and reported 4.7% against a real 70.8% — backwards, since adding a well-tested package lowered the number.
- The repository is onboarded onto `gt` repo governance, and this repo now consumes its own default stack. It builds `agtk` from its default branch and syncs with that, rather than installing a release: it is the one consumer whose schema necessarily runs ahead of every release, because it is where the schema is added.
- Rendered output — `.claude/`, `CLAUDE.md`, `.mcp.json` — is no longer committed. The tracked inputs are the manifest and its lockfile; `.gt.yaml` regenerates the rest on clone and on every new worktree.

### Compatibility

- **Schema additions, all optional:** `memory.root` (defaults to `.agents/memory`) and `memory.agent` (no default — curation is the one operation that spends money, so a repo names its provider or curation does not run). Both are honoured **only in the entry manifest**; a stack reached through `extends:` that sets `memory:` gets a diagnostic instead of silently relocating another repo's committed notes.
- **Manifests decode strictly, so upgrade the binary before you adopt the field.** An older `agtk` pointed at a manifest that sets `memory:` fails to parse it. This is the same ordering constraint as any schema addition here, and it is a hard failure rather than a warning by design.
- **`requires:` resolution can add definitions to your render.** A stack that listed a definition without its dependency now gets the dependency too, so expect new files under `.claude/` on the first sync after upgrading. Each addition is reported as a `pulled_requirement` diagnostic by `agtk plan` — run that first if you want to see the set before it lands.
- **`agtk memory curate` is deliberately not pre-approved** in `skill-permissions`. It spends money and rewrites `notes/`, so it stays a prompt answered deliberately.
- **Building from source requires Go 1.26.6**, a floor set by `agentic-driver`. Consumers installing a release binary are unaffected.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`), then `agtk lock` and `agtk sync`. A plain `agtk sync` will not pick this up — the lockfile pins a SHA. Consumers pinned to a tag also need to bump the ref in `.agentic-toolkit.yaml` to `@v0.11.0`.

### Known gaps

- **Nothing deduplicates candidates across concurrent explorers.** `candidates/` is one file per finding so parallel writes do not conflict, but two explorers that find the same mechanism stage it twice.
- **Renaming a note discards its hit history**, since only hits on known names count. A renamed note reads as cold.
- **The hit rate in `agtk memory stats` covers the current checkout only.** `.hits.jsonl` is gitignored so reads never become PR noise, and the consequence is that a fresh clone reports 0% over a store that is heavily used elsewhere. `stats` labels the scope and suppresses the cold list as a prune signal until reads reach the note count.
- **A claim quantified over *packages* has no anchor shape that watches the right set.** `**` is banned, so no one-level glob notices a fourth package acquiring the thing the claim is about.
