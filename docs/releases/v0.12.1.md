## v0.12.1 — the codex panel answers, and a review nobody performed stops suppressing the one that would

A patch release fixing two bugs that compound: **no codex reviewer could answer, and the empty review it posted then blocked the re-run.** Together they made `agtk code-review run --pr` on this repo's default roster produce a pull request that displays a review, having reviewed nothing, and refuse to try again.

### Every codex reviewer died on the answer schema

```
$ agtk code-review run --pr 86
correctness-codex#1 ran and did not answer: codex ended the turn:
  "code": "invalid_json_schema",
  "message": "Invalid schema for response_format 'codex_output_schema': In context=
    ('properties', 'findings', 'items'), 'required' is required to be supplied and to be
    an array including every key in properties. Missing 'suggestion'."
```

OpenAI's strict structured-output mode refuses a schema where a key in `properties` is absent from `required`, and it refuses it at the provider rather than at the model — so the run dies having read nothing. `findingSchema` and `judgeSchema` both declared `suggestion` and both omitted it from `required`.

`suggestion` is now `["string", "null"]` **and** required, in both schemas — the spelling `start_line` and `end_line` already used. Required keeps the schema valid; nullable keeps a reviewer with nothing to suggest from having to invent one. A declined suggestion decodes to the empty string every consumer already guards on, so nothing posts the word "null" as advice.

The defect was invisible locally because Claude's schema handling accepts either spelling. The worktree roster is claudecode and the PR roster is codex, so the only place it bit was the one place nobody was watching it run.

A new test walks each schema this package sends a provider and asserts generically that every key in a `properties` appears in that object's `required`. It reads the JSON rather than listing today's field names, so a schema that gains a field fails the test instead of the next pull request review.

### A review that reached no verdict suppressed the review that would

```
$ agtk code-review run --pr 86
pedromvgomes/agentic-toolkit#86 already carries a review of e6b791a4.
No panel ran: nothing was spent and nothing was posted.
```

Both reviews it was counting had reached **no verdict** — the schema failure above. Re-running required `--force`, which is backwards: a review where nobody looked is a record that nothing examined the change, and reading it as "this head is reviewed" is the one mistake the engine refuses everywhere else. Here it did real damage, because the marker that records the failure was the thing preventing anyone fixing it.

A head now counts as reviewed only when a review this App authored carries a marker reading `verdict=complete`. The data was already being posted and simply never read back: the reviews query asked for each review's commit and authorship and not its body, so the marker was out of reach.

- `ReadReviewedCommits` is **gone**, and the check reads `ReadSubmittedReviews` — the reader approval already used, which returns each review's commit, body and authorship. Two queries against the same connection for the same reviews, one of which could not answer the question, was the duplication the old cheaper query bought.
- **An App-authored review carrying no marker `agtk` can parse counts as no verdict.** It is the safer of the two readings: being wrong costs one re-run, where the other direction costs a pull request that displays a review nobody performed.
- `--force` is unchanged, and still the way past a genuinely complete review.

The no-op's wording now says *completed* review, in both the terminal and the `--json` `reason`.

### Compatibility

- **No CLI changes, no manifest changes, no definition changes.** No flag, subcommand or configuration key was added, removed or renamed.
- **`internal/githubapp` is not a public API.** Removing `ReadReviewedCommits` is internal to this module.
- **A pull request already carrying a complete review behaves exactly as before.** What changes is only which reviews count as complete.
- **Building from source still requires Go 1.26.6.**
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`). No `lock` or `sync` is required — nothing a consumer renders has changed.

### Known gaps

A pull request reviewed by a pre-v0.12.1 binary carries reviews that reached no verdict, and the fix reads those correctly — they no longer suppress. A head whose *only* review was posted by the old binary and did reach a verdict is unaffected either way.

The marker is the sole record that a review happened; nothing is persisted between runs. A review whose body a person edits past the point where the marker parses reverts to "no verdict", which re-reviews rather than refusing — the safe direction, but it is a re-run somebody did not ask for.
