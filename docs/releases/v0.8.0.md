## v0.8.0 — chrome-devtools MCP, and a real fix for MCP server rendering

A feature release on top of v0.7.0: a new `chrome-devtools` MCP definition, and a bug fix for how MCP servers are rendered for Claude Code that affects every existing MCP definition, `context7` included.

### Fix: MCP servers now render to `.mcp.json`, not `settings.json`

Claude Code only discovers project-scoped MCP servers from `.mcp.json` at the project root — it does not read a `mcpServers` key from `settings.json`. The Claude adapter had rendered MCP definitions into `settings.json` since MCP support was added (v0.7.0's `context7` addition included), so **every MCP server ever declared through this toolkit has silently never actually connected** for any consumer. `claude mcp list` never showed it; there was no error.

`internal/adapters/claude/mcp.go` now renders `mcpServers` to `.mcp.json`, using the same mixed-ownership `_meta.agtk.managed` tracking `settings.go` already used: re-renders drop servers removed from the plan while preserving anything else already in the file. `settings.go` no longer touches `mcpServers` at all.

User scope (`--scope user`) is a documented no-op for MCP servers: Claude Code stores those in `~/.claude.json` under a per-project `"projects"` map, a different shape from `.mcp.json`'s flat object, not implemented yet.

**Action for existing consumers:** re-run `agtk sync` after upgrading. Any MCP server you'd declared will start actually connecting for the first time.

### New: `chrome-devtools` MCP server definition

A stdio MCP definition for [`chrome-devtools-mcp`](https://github.com/ChromeDevTools/chrome-devtools-mcp) (`npx chrome-devtools-mcp@latest`) — drives a real Chrome instance over the DevTools Protocol for browser automation and debugging. Its `take_screenshot` tool accepts a `filePath` argument that writes screenshots straight to disk, unlike the `claude-in-chrome` extension's `save_to_disk`, which currently drops screenshot bytes silently. Not wired into `stacks/default.yaml` — it's heavier than `context7` (spins up a Chrome process), so it's opt-in per consumer.

### New: Hermes Tweet skill

A new skill definition for X/Twitter research, read workflows, social monitoring, and approval-gated social actions via Hermes Tweet with Xquik. Thanks to @burakbayir1 for the contribution.

### Compatibility

- **No schema changes.**
- **Behavior change, not a breaking one:** MCP servers now land in `.mcp.json` instead of `settings.json`'s `mcpServers` key. Since the old location never actually worked, this can only fix previously-broken configurations — there's no prior working state it could regress.
