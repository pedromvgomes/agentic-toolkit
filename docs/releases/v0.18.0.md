## v0.18.0 — a curator that cannot report success over a half-curated store, and code review from a machine with no App

### `agtk memory curate` no longer exits 0 over a half-curated store

A curation run could delegate to a background subagent, have `claude -p` drop it at its own
idle-wait ceiling, and exit 0 having written notes but removed no candidates, stamped no anchors and
regenerated no index. Nothing after the child exited looked at the store. It does now:

- **The curator cannot delegate.** The Agent and Task tools are denied on every run through
  `agentic.Request.DisallowedTools` (agentic-driver v0.10.0), and the `memory-curator` roster the
  prompt used to delegate to is gone: the curator's policy is inlined into the run. A real run on a
  provider that cannot deny tools is refused before the child starts; a `--dry-run` is not. No
  shipped provider is affected today, since `codex` already refuses a real run for having no
  per-tool allow-list. `agtk memory curate --check` prints the deny list (`deny:` in text,
  `disallowed_tools` in JSON) beside the grant.
- **Every run files a completion report.** The child's final turn is a JSON object naming the
  candidates it resolved, the notes it retracted and the notes it touched. A run that produces none
  fails, whatever `is_error` says.
- **The report is checked against the store in both directions**, using a snapshot taken before the
  child starts. What it claims has to be true (a resolved candidate was staged and is gone, a
  retracted note existed and is gone, a touched note parses, is stamped and lints clean, the index
  is current), and everything that changed on disk has to be in it. The second direction is the
  one that catches a run cut off after writing notes and reporting nothing. A failure exits
  non-zero naming each mismatch and the command that repairs it, prints the curator's own account
  of the run first, and rolls nothing back. `--dry-run` is exempt.
- **`--limit N`** points a backlog run at the oldest N staged candidates, so a large backlog can be
  worked in bounded passes. It shapes the job description and does not narrow the tool grant, and it
  cannot be combined with named notes or `--stale`.
- The curator's prompt now requires `description:` values to be quoted, so a colon in the text can
  no longer produce frontmatter that does not parse.

### Unreadable notes are no longer skipped in silence

- **`agtk memory index` and `agtk memory audit` exit non-zero** when a note does not parse. Both
  still produce their normal output for the notes that did, and name each unreadable file once.
  Before, both warned on stderr and exited 0, so a store could quietly index 51 of 52 notes.
- **`agtk memory stats` is unchanged**: its exit code means the store itself could not be read, and
  the memory-first instruction and the session-start hook depend on that.
- **`agtk memory anchor a b c`** stamps every note that parses and reports the rest, exiting
  non-zero, instead of refusing the whole batch because one name did not resolve. An unparseable
  note is reported as such, not as "no note named".

### `agtk code-review` from a machine with no GitHub App registration

- **Reads fall back to a plain token.** `explain --pr` works with `GH_TOKEN` or `GITHUB_TOKEN`
  (in that order) and no registration. A token-backed read never marks a comment as the App's own,
  so a token belonging to the change's author cannot silence a finding. Posting and approving
  still need the App (ADR 0019).
- **A relay posts on the machine's behalf.** With `AGTK_CODE_REVIEW_RELAY=owner/repo` naming a
  repository the App is installed on, `agtk code-review run --pr` runs the panel locally and
  dispatches only the posting to a workflow there; `agtk code-review approve` is relayed the same
  way. The relay repository's default branch must be named `main`, and `--json` is refused under a
  relay (it would describe the relay's run, not the review). New subcommand `agtk code-review post`
  reads a computed review on stdin and posts it; it is what the relay's workflow runs, and it
  refuses a review made against a commit that is no longer the pull request's head (ADR 0020).
  A relay whose workflow builds `agtk` from source until a release ships `post` can now install
  this release instead.

### Also in this release

- `agentic-driver` v0.9.0 → **v0.10.0**. The prompt for a `claude -p` or `codex exec` run travels on
  the child's stdin instead of argv. A review prompt embedding a whole diff exceeds Linux's 128 KiB
  limit on one argument, so `agtk code-review run` failed to start with `argument list too long`;
  it no longer does.
- `install.sh` resolves the latest release through `github.com`'s redirect and falls back to the API
  only when that fails, so it works where `api.github.com` is rate-limited or blocked.
- `wrap-session` recognises an agtk-managed repository and changes rendered files through their
  sources (the manifest's `context:` file, `agentic/rules/`, `agentic/instructions/`) followed by
  `agtk render`, rather than editing output the next render overwrites. The shouted wording in a few
  instructions is toned down.

### Compatibility

- **No schema changes, and no definition changes** beyond the `wrap-session` and curator-prompt
  wording above.
- **Behaviour that now fails where it warned:** `agtk memory index` and `agtk memory audit` exit
  non-zero on a store holding an unreadable note. A CI job that runs either on such a store turns
  red until the note is fixed; the error names the file.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`). Consumers pinned to a
  tag can bump the ref in `.agentic-toolkit.yaml` to `@v0.18.0`.
- **Building from source still requires Go 1.26.6.**
