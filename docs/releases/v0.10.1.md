## v0.10.1 — tagged releases are installable

A patch release fixing one bug: **no tagged release of this repo could be consumed by tag.** A consumer pinning `@v0.10.0` — or `@v0.9.0`, or any tag back to `v0.7.0` — got a hard failure from `agtk lock`:

```
agtk: command failed
  → lock
  → stack "<entry>" extends[0] ("github.com/pedromvgomes/agentic-toolkit.git/stacks/default.yaml@v0.10.0")
  → provider
  → sha mismatch: fetched 67173a65… but lockfile pins 06f4a7e2… for …@v0.10.0
```

### Cause

Every release tag here is annotated, and an annotated tag is a git object in its own right — distinct from the commit it points at. `git ls-remote <url> v0.10.0` reports the *tag object's* SHA:

```
06f4a7e2…  refs/tags/v0.10.0        ← the tag object
67173a65…  refs/tags/v0.10.0^{}     ← the commit, only shown when the pattern asks for it
```

`gitResolveRef` took the SHA from the first line and recorded it as the pin. `gitFetch` then checked the ref out, landing on the *commit*, and the verification comparing the two could never succeed. Branches and `HEAD` were unaffected — they have no second object to peel — which is exactly why the existing resolver tests, which use branch refs against synthetic fixtures, never caught it.

### Fix

`gitResolveRef` now probes both `<ref>` and `<ref>^{}` and prefers the peeled line, so the recorded SHA is always the commit a later fetch will produce. Peeled commits are keyed by the refname they came from, so a probe matching both a branch and a tag of the same name applies the peel only to the tag.

Two tests cover it end to end against a real local git repo: an annotated tag must resolve to its commit, and a lightweight tag — which points straight at the commit and has no peeled line — must keep resolving exactly as before.

### Compatibility

- **No schema changes, no definition changes.** `stacks/default.yaml` and every definition are byte-identical to v0.10.0; this release is the CLI fix alone.
- **The fix lives in the `agtk` binary, not in the tag.** An older binary still fails against every tag, including this one. Upgrade first with `agtk update` (or re-run `install.sh`), then pin `@v0.10.1`.
- **Action for existing consumers:** upgrade the binary, then `agtk lock` and `agtk sync`. Consumers who worked around this by pinning a branch or a commit SHA can move back to a tag.
