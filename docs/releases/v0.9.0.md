## v0.9.0 — pre-pr-review reviews the whole branch, and every language in it

A definition-only release on top of v0.8.0. No CLI or schema changes: everything here is in the `pre-pr-review` skill, which had three bugs that silently narrowed what it reviewed, plus a structural limit that made polyglot branches awkward.

### Fix: untracked files were invisible to the review

The skill assembled its diff from `git diff` (worktree) and `git diff --cached` (staged), and claimed that combination meant "nothing on the worktree is missed." Neither command shows untracked files. **A new file you hadn't `git add`ed was silently excluded from every reviewer** — the most common shape of new code in a pre-PR review, and the failure was invisible because the skill reported no error and the reviewers simply never saw the file.

`scripts/capture-diff.sh` and `scripts/list-changed.sh` now emit a third section built from `git ls-files --others --exclude-standard`, rendering each untracked file through `git diff --no-index` so it reaches reviewers as a normal add-everything hunk.

### Fix: parent detection crashed on repos whose default branch isn't `main`

When no local branch shared history with `HEAD`, `scripts/detect-parent.sh` fell back to a literal `PARENT=main`. On a `master`, `trunk`, or `develop` repo the subsequent `git merge-base HEAD main` failed under `set -euo pipefail`, so the script died mid-run and emitted no JSON at all. The skill had nothing to parse and the review couldn't start.

The fallback now resolves the real default branch — `origin/HEAD` first, then a `main`/`master`/`trunk`/`develop` probe across local and remote refs — and returns a structured `{"current":…,"error":…}` object instead of dying when nothing resolves. Remote branches are now candidates too (excluding the current branch's own upstream), so a parent that exists only as `origin/feature-x` is detected rather than skipped.

### Fix: partially-staged files were reviewed twice

Staged and unstaged changes were emitted as two separate sections, so a file with both staged and unstaged edits appeared in both — inviting reviewers to file the same finding twice. Both scripts now emit a single `git diff HEAD` section covering all worktree changes.

### New: polyglot branches get one panel per language, in one run

The skill previously picked exactly one stack per invocation and told the user to run the review twice for a branch spanning Kotlin and React. That guidance was easy to miss, and the second run started from scratch: separate conventions extraction, separate triage table.

Phase 1 now partitions the changed files into per-stack buckets plus an unclaimed bucket. Any bucket holding at least 3 files or 20% of the diff gets its own reviewer panel, and **all panels fan out in parallel in a single invocation, consolidating into one triage table**. Each panel's diff is scoped to its own files, so Kotlin reviewers no longer read `.tsx`. Findings carry a stack-prefixed category (`kotlin-spring/security:injection`) so consolidation can tell converging panels apart. Buckets below the threshold fold into the dominant panel as context — 40 Kotlin files and one stray `.tsx` doesn't warrant a React panel.

### New: `general` fallback panel

A diff that matched no stack previously had no defined behavior beyond "no default is suggested" — a branch of pure shell, CI, or infra changes had no panel to run. There is now a `general` roster (`prompts/general/`) with language-agnostic security and correctness reviewers covering shell scripts, CI workflows, container and IaC config, and languages with no dedicated roster.

It's used when nothing else matches, and also runs as its own panel alongside language panels when the unclaimed files clear the significance bar (3 files or 20% of the diff). Below that bar, a handful of CI or script files still folds into the dominant language panel as context rather than getting a dedicated reviewer — the same threshold that governs every other bucket.

### Improved

- **One approval gate instead of three.** Parent branch, stack selection, and scope confirmation now arrive as a single `AskUserQuestion` with three questions. The conventions gate stays separate since it depends on the extractor's output.
- **Exclusions are applied by the scripts, not by hand.** Both scripts take pathspecs after the base ref — `!`-prefixed to exclude, anything else to restrict — so excluded files are dropped by `git` rather than by the orchestrator editing a large diff string. This is also what scopes each panel's diff.
- **Repo-specific content removed from the generic prompts.** The `kotlin-spring` security prompt named another repo's internals (`EntityRedactor`, a Kafka-publishing domain), and Phase 5 hardcoded that repo's `unitTest` gradle task. Repo specifics are the conventions extractor's job; Phase 5 now prefers a test command the repo documents or already runs in CI, falling back to stack conventions only when the repo names none.
- **Sharper stack detection.** `package.json` no longer counts toward React (it matched any Node project) and `internal/` no longer counts toward Go (the substring is common in every ecosystem).
- **Convention docs now include `CLAUDE.md`** and `.claude/CLAUDE.md`, an odd omission for a Claude toolkit. Duplicate paths are deduped when a module argument resolves to the repo root.
- **Confidence is surfaced rather than collected and ignored.** It appears as a column in the triage tables, and a low-confidence RED is demoted to AMBER — a reviewer who isn't sure shouldn't produce a merge blocker. Findings two agents reported independently are exempt.

### Compatibility

- **No schema changes, no CLI changes.** The `agtk` binary is identical in behavior to v0.8.0 apart from the release-workflow dependency bump below.
- **No stack changes.** `pre-pr-review` was already in `stacks/default.yaml`; the new `prompts/general/` files ship automatically with the skill bundle.
- **Action for existing consumers:** re-run `agtk lock` and then `agtk sync`. A plain `agtk sync` will not pick this up — the lockfile pins a SHA, and sync only re-locks when the lockfile is older than your config file. Consumers pinned to a tag also need to bump the ref in `.agentic-toolkit.yaml` to `@v0.9.0`.
