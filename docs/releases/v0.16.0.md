## v0.16.0 — the feature flow converges its pull request, and a re-review reads only what changed

`/implement-handoff` ran its review loop on the working tree, opened the pull request and posted
a second review. Then it stopped. The findings that review posted were left for somebody to
notice. The handoff was closed after one look at the checks, and that look read a still-running
scan as a pass. **The flow now loops on the pull request as well: review, answer every thread,
push, review what changed. It waits for the checks to finish, and closes the handoff only once
both loops came back clean and every check passed.** Re-reviewing a pull request after a push
now costs a review of the push, not of the whole branch again.

### A pull request re-review reads what changed since its last verdict

```
$ agtk code-review run --pr 46
scope:    delta since <reviewed head>, the last head a review by this installation reached a verdict on
manifest: built-in default
range:    <reviewed head>...<new head>
panel:    standard
```

After a push, `agtk code-review run --pr` reads only what changed since the last head a review
by this installation reached a verdict on. The panel is sized from that delta: a fix to an auth
file still escalates, and a fix to a README no longer pays for `deep` again. It reads the whole
change instead when the branch was rewritten, the base was merged in, or no earlier review
reached a verdict, and it says which. `--full` reads the whole change regardless.

Only the diff narrows. The manifest, the prompts and the convention documents are still read at
the merge base, so a branch still cannot write the rules it is judged by (ADR 0007). Comments
are still placed against the pull request's whole diff.

`explain --pr` reports the same scope and sizes the panel the same way. The JSON output of both
carries a `scope` object (`kind`, `since`, `reason`), and `pull_request.reviewed_range` names the
range actually read.

### Approval walks the chain of reviews

A narrowed review records `since=<commit>` in its marker. `agtk code-review approve` walks from
the head's review back through each `since` to a review of the whole change. A missing or
incomplete link is refused, with `--full` as the remedy, because part of the change was read by
nobody.

A finding an earlier review made, and the head's review did not repeat, is **carried**. The
head's review never read that code unless it changed, so the finding's absence clears nothing.
It is cleared by a false-positive marking, or by an answer from an account that can push on a
thread that is then **resolved**. A finding the head's review repeats is held to the existing
rule. See ADR 0018.

### New default skill: `review-pull-request`

The published-side counterpart of `review-implementation`. Each pass reviews the pull request,
then runs `pr-review-resolver --unattended` over every unresolved thread: agtk's, bots', and
people's. The resolver fixes what it judges valid, replies on each thread with the fixing
commit, with `agtk: false positive: <reason>`, or with a direct answer, and pushes. The next
pass reviews what that push changed.

The loop stops on no verdict, clean (nothing waiting for an answer), stalled, or at the fifth
pass. **It never resolves a thread.** Resolving is where a person agrees with the agent's fix or
its false-positive call, and approval waits for it. The report lists every marking the agent
made and every thread waiting for you.

### `pr-review-resolver` gains `--unattended`, and stops guessing reviewers

`--unattended` skips the findings prompt and plan mode, which a loop has nobody to answer. It
decides each thread itself, verifies every reply, and resolves nothing. In both modes, re-review
is requested only from people who commented. It is never requested from a bot, and never from
a login nobody saw on the pull request.

The resolver also replies on the review thread itself, against the root comment's id, and
verifies that every reply landed (#112).

### `open-pr` and `implement-handoff` finish the job

- `open-pr` posts its review with `--no-fix`, then hands the pull request to
  `review-pull-request`.
- `implement-handoff` waits for the pull request's checks with `gh pr checks --watch
  --fail-fast`. The wait returns as soon as they finish; 30 minutes is only the ceiling. A
  failing check, a check still running at the ceiling, or a pull request loop that did not come
  back clean leaves the handoff where it is.
- `implement-handoff` no longer narrates a task dispatch without making the call (#111).

### New default skill and instruction for agentic-toolkit consumers

`stacks/default.yaml` ships `using-agentic-toolkit`, a skill for changing what agent tooling a
repo ships through `agtk`: where each category's files go, which command to run afterwards, and
which definition wins a collision. It also ships the `rendered-output-stays-out-of-git`
instruction: commit `.agentic-toolkit.yaml` and its lockfile, and gitignore the rendered output
with root-anchored patterns (#110).

### Compatibility

- **New flag:** `agtk code-review run --full`. It is accepted only with `--pr`.
- **Behaviour change:** a `run --pr` after a push reads the delta by default, sizes its panel from
  it, and may pick a smaller panel than the first review did. Pass `--full` to get the previous
  behaviour for one run.
- **Markers:** reviews posted before this release carry no `since` and read as reviews of the
  whole change, so existing pull requests approve exactly as before.
- **Approval:** a pull request whose head was reviewed as a delta needs every carried finding at
  or above the floor marked a false positive, or answered and resolved.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`), then `agtk sync` in
  repos on `stacks/default.yaml` to pick up `review-pull-request` and the changed skills.
