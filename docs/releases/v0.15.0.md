## v0.15.0 — published text carries no authoring footer, and a guard enforces it

Coding agents append attribution to what they publish by default: a `Co-Authored-By:` trailer, a
`Claude-Session:` line, a link back to the session, a "Generated with" line. The git instruction
already said not to, but an instruction competes with a harness that asks for the opposite, and
it loses often enough to matter. This release turns the rule into an instruction of its own and
puts a PreToolUse hook behind it that refuses the command before the text leaves the machine.

### New default instruction: `no-authoring-footers`

`stacks/default.yaml` now ships an instruction covering every kind of published text — commit
messages, PR titles and descriptions, review replies, issue comments, release notes and tag
messages — rather than only commits and PR descriptions. It bans four shapes: a
`Co-Authored-By:` line, a `Claude-Session:` trailer, a link to a `claude.ai/code/session` page,
and a line opening with "Generated with". It tells an agent whose command was refused to remove
the footer and retry, never to route the same text past the guard another way.

The `git` instruction's two attribution bullets collapse into one that points at it, so the rule
is written once.

### New default hook: `agtk guard footers`

`stacks/default.yaml` also ships `no-authoring-footers-claude-pre-tool-use`, a Claude Code
PreToolUse hook on `Bash` that pipes the hook payload into the new `agtk guard footers`
subcommand. It exits `2` to deny and names the footer it found; everything else is allowed.

The guard parses the command as shell (`mvdan.cc/sh`) rather than matching it as text, so it
judges what actually runs:

- **What publishes.** `git commit`, annotated `git tag`, `gh pr`/`gh issue`
  create/edit/comment/review, `gh release` create/edit, and `gh api`. Git's global options
  (`git -C repo commit`) and a flag between `gh pr` and its action word are read past, not
  mistaken for a non-publishing call. A command the parser rejects is judged on its raw text
  whenever it names `git` or `gh`.
- **Wherever it sits.** In a list, pipeline, subshell or command substitution; behind `command`,
  `builtin`, `exec`, `nohup`, `time`, `nice`, `timeout`, `env` (including `env -S`), `sudo`,
  `doas` or `xargs`, nested to any depth; or inside a script handed to `sh`/`bash`/`zsh`/`dash`/`ksh
  -c` or to `eval`.
- **Where its text comes from.** The whole command text, plus every file the text is read from:
  `-F`/`--file`, `--body-file`, `--notes-file`, `gh api` `key=@file` fields and `--input` bodies
  (a JSON body's string values are checked as well as its raw text), and any file the script reads
  with `cat FILE` or `< FILE`, so `body=$(cat body.md); gh pr create --body "$body"` is checked.
  Quoted and escaped paths are read in full, and relative paths resolve through `git -C`,
  `env -C`, `sudo -D` and every `cd`/`pushd` in the script.

What it cannot see: a value that comes from the environment or from an earlier shell call, and a
script file run as `bash script.sh`. The instruction still applies there; the hook has nothing to
check it against.

The hook probes `agtk guard footers --help` first and exits `0` when the installed binary lacks
the subcommand, so a consumer who syncs this stack before upgrading `agtk` gets no hook errors —
just no enforcement until the binary catches up.

### The feature flow says how stage two starts

After `/plan-feature` is approved, the flow told the user to run `/clear` and said the
session-start hook would pick the handoff up. A SessionStart hook can add context but cannot begin
a turn, so the session sat idle until the user typed something. `plan-feature`, `write-handoff`
and `implement-handoff` now name both steps — run `/clear`, then run `/implement-handoff` — and
`docs/FEATURE-FLOW.md` describes the hook as the reminder it is. The hook itself is unchanged.

### Compatibility

- **No breaking changes.** No manifest, stack or CLI shape changes.
- **Consumers of `stacks/default.yaml` gain a PreToolUse hook on `Bash`.** It runs `agtk guard
  footers` on every Bash call and denies only a publishing call carrying a banned footer. A
  command that reads a file with `cat` while also publishing has that file checked too, so a
  footer-shaped line in an unrelated file read in the same command can be refused.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`), then `agtk lock` and
  `agtk sync`. Consumers pinned to a tag also need to bump the ref to `@v0.15.0`. Syncing the stack
  on an older binary is safe: the hook stays inert until `agtk` is upgraded.
