## v0.21.0 — the backlog is GitHub issues, and handoffs are retired

### Breaking: handoffs are removed

The feature flow no longer has local handoffs. A backlog item on a GitHub issue replaces them.

- **`stacks/default.yaml` no longer carries `write-handoff`, `implement-handoff` or the handoff
  `SessionStart` hook** (`handoff-claude-session-start`). Their skills, the hook and the handoff
  template are gone from the catalog.
- **`agtk handoff` is removed.**
- **What replaces each:**
  - `write-handoff` → `write-backlog-item`, including its mid-work save, which writes the place
    you stopped as an issue carrying neither a task list nor a slice;
  - `implement-handoff` → `implement-backlog-item`.
- **Re-render after upgrading.** A consumer who upgrades the binary before re-rendering sees one
  `Note:` at each session start (`agtk handoff list` failed, so handoffs could not be checked)
  until `agtk render` removes the hook from `.claude/settings.json`. Run `agtk render` once after
  moving the ref.

`CONTEXT.md` defines the feature flow on backlog items, and ADR 0014 (a handoff is trusted
structurally) is superseded by ADR 0028 (a backlog item is trusted by who wrote it).

### `agtk backlog` reads a repository's backlog from its GitHub issues

Three read-only subcommands over the open issues that carry an `agtk:` label. Nothing posts,
labels or edits.

- **`agtk backlog list --repo owner/repo`** lists every item in issue-number order, with its
  state, predecessors and Feature. `--json` emits an array.
- **`agtk backlog verify owner/repo#N`** decides whether an item may be acted on (ADR 0028): the
  author and every editor of the body have write access, the latest `agtk:queued` label came from
  the trusted App or an account with write access, and no body edit is at or after that label.
  Only the body is the work; no comment is read. Trusted, it exits 0 and prints
  `sha256 <hex>` and then the body byte for byte; refused, it exits 1 and names whether the item
  is "not trusted" or "could not determine". `--trusted-app <slug>` names the App whose
  `agtk:queued` label counts; without it only an account with write access does. `--json` emits
  the answer, trusted or refused.
- **`agtk backlog labels`** prints the canonical `agtk:` label set, each with its colour and
  description. `--json` emits an array.

All three read with the token in `GH_TOKEN` or `GITHUB_TOKEN`, never as an App registration, even
on a machine that holds one.

### `agtk pr wait` waits on a pull request so a session does not

`agtk pr wait owner/repo#N` polls a pull request's check runs, commit statuses, comments and
review threads until one poll reaches a verdict, and exits once with that verdict's code (ADR
0029). It reads with a token only and writes nothing.

| Exit | Verdict |
|---|---|
| 0 | clean: every check run passed, every status is success (`lydite/referral` may stay pending) and no review thread is waiting |
| 2 | action needed: a check or status failed, or a thread is waiting; each is named |
| 3 | cap reached: `--cap` (default 2h) passed with something still pending |
| 4 | head moved: run it again to wait on the new head |
| 5 | closed or merged |
| 6 | could not read: no token, or three failed polls in a row |
| 7 | no checks: still none on a second poll |
| 1 | did not start: a malformed argument or flag |

`--poll` (default 5m) sets the wait between polls and `--json` emits the verdict as one object.

- **Only the newest workflow run of each workflow and event is judged.** Every `pull_request`
  event, an edit of the description included, starts a new run on the same head, and a run the
  workflow's `concurrency` cancels leaves cancelled and failed check runs beside the newer run's.
  Those superseded check runs no longer fail the wait. A token without `actions: read` reads no
  workflow runs, so it falls back to judging every check run.
- **lydite's surviving-mutant threads are left to lydite's failing check.** An unresolved thread
  whose opening comment and latest comment are both by the lydite App's bot account
  (`<--lydite-app slug>[bot]`, `lydite[bot]` by default) is neither waiting nor answered; lydite's
  own check carries the verdict: pending while lydite runs, action needed once it fails, clean
  once it passes and the comment is gone. A thread anyone else opened or spoke last on is judged
  as any other.

### Plan, write and implement work as backlog items

- **`/plan-feature` step 6** puts the approved plan on the GitHub-issue backlog: a Feature, and a
  backlog item for each slice, the later slices as stubs.
- **`write-backlog-item`** writes an item's body from the plan, fills a stub once its predecessor
  is done, and saves your place mid-work. It never queues anything.
- **`implement-backlog-item owner/repo#N`** implements an item that `agtk backlog verify` has
  trusted, then reviews it and opens the pull request, with the item ending `agtk:in-review`.
  Interactive, a person confirms the task list; unattended, every stop is a comment on the item
  plus a label.
- **The review skills describe the halt a backlog item resumes from.** `review-pull-request` and
  `review-implementation` say that `implement-backlog-item` treats anything but a clean outcome as a
  halt and leaves its backlog item where it is so the work can be picked up again, and
  `docs/FEATURE-FLOW.md` describes the flow through backlog items only.
- **An unattended run acts only on trusted text.** It passes `--checked-authors` through
  `open-pr` and `review-pull-request`, so the review loop works only threads whose every comment
  is from the review App, an account with write access or the loop's own. A thread holding any
  other comment ends the loop as an unchecked thread, linked and never read, except a thread
  whose comments are all by `lydite[bot]`, which is left alone; and a review summary
  or conversation comment from an unchecked author is listed and left unread. When it fills the
  next stub it never reads the stub's own title or body, since nobody verified who wrote them.
- **A lydite surviving-mutant thread is fixed and gets no reply.** `pr-review-resolver` kills the
  mutant with a test and pushes; lydite removes its own comment on its next run. The skill never
  suppresses the mutant and never resolves the thread.
- **A backlog item's branch stays pushable without a force push.** One branch per item, never
  reused after its pull request merges. A branch is brought current by merging the base into it,
  never by a rebase, an amend or a reset. A remote branch whose commits are all already on the
  base (found by `git cherry`, or by a clean merge that yields the base's own tree) is started
  fresh from the base and joined by `git merge -s ours`, so the plain push moves it forward.
  Work on the remote branch that is not on the base stops the run with `agtk:needs-human`.

### For the Factory

The Factory starts `/implement-backlog-item owner/repo#N --unattended --sha256 <hash>
[--trusted-app <slug>]` and relies on:

- **`--unattended`**: nobody is at the keyboard. Nothing waits for a yes, each task is pushed
  after it is committed, and each stop is a comment plus a label.
- **`--sha256 <hash>`**: the SHA-256 of the body the Factory verified before it started the
  session. Required with `--unattended`. The session compares it, as exact lower-case hex, with
  the hash `agtk backlog verify` prints and stops with `agtk:needs-human` when they differ.
- **`--trusted-app <slug>`**: the Factory App's own slug, passed through to `agtk backlog verify`.
  It comes from the Factory and nowhere else. Without it, an item the Factory App queued is
  refused.
- **`agtk:queued` stays on until the session has verified the item.** Verify trusts only an item
  carrying it. The session removes `agtk:queued` itself, when the item ends `agtk:in-review` or
  stops.
- **`actions: read` on the token `agtk pr wait` uses.** Without it the wait cannot tell
  superseded workflow runs apart and judges every check run.

### Also in this release

- **The git instruction splits into a cloud path and a local path.** A session reads
  `AGTK_CLOUD`: in a cloud session it runs `agtk cloud init`, verifies the committer identity
  and uses the GitHub MCP tools; locally it keeps the `gt` bare-repo layout and `GH_TOKEN` rules.
  Commits and pull requests carry no session references (#194).
- **The usage parser stamps each row** with its Project, repo, Claude account and host. Project
  comes from `AGTK_PROJECT`, else the origin remote's `owner/name`, else the working directory's
  name; the account from `CLAUDE_CODE_ACCOUNT_UUID`, `CLAUDE_CODE_ORGANIZATION_UUID` and
  `CLAUDE_CODE_USER_EMAIL`; the host is `cloud` when `CLAUDE_CODE_REMOTE` is set, otherwise
  `local`. A value that cannot be determined is null (#195).
- **A per-machine ledger and outbox for unsent usage rows** live under the XDG state directory,
  behind a file lock (unix only). Nothing in the CLI calls them yet (#196).
- **The attribution setting works.** `no-attribution` sets `attribution.commit` and
  `attribution.pr` to empty strings; a boolean fails Claude Code's settings validation, so the
  trailer and the pull-request line were not switched off (#197).
- **`goreleaser/goreleaser-action`** 7.2.3 → 7.3.0 in the release workflow (#198).
- **The remote slug parser moves into its own `gitremote` package**, shared by the review and
  usage code, with no change in behaviour (#193).

### Compatibility

- **No schema changes.**
- **What `stacks/default.yaml` renders changes for existing consumers:**
  - `write-handoff` and `implement-handoff` disappear from `.claude/skills/`;
  - the handoff `SessionStart` hook disappears from `.claude/settings.json`;
  - the git instruction gains its cloud and local paths;
  - `attribution.commit` and `attribution.pr` render as empty strings.
- **Action for existing consumers:** `agtk update` (or re-run `install.sh`), then `agtk render`.
  Consumers pinned to a tag can bump the ref in `.agentic-toolkit.yaml` to `@v0.21.0`.
- **Anything calling `agtk handoff`** must move to `write-backlog-item` and
  `implement-backlog-item`.
